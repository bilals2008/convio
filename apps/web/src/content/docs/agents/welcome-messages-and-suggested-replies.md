# Welcome messages and suggested replies

The first thing a visitor sees decides whether they type at all.

## Welcome message

A short message shown when the conversation opens, before the visitor has said anything. It sets expectations in one breath, and it is the cheapest conversion improvement available to you.

It is optional. Without one, the widget opens on an empty input and the visitor has to guess what it is for.

## What a good one does

- **Names what the agent does** — not who it is, what it does
- **Sets scope** — so people do not ask it things it cannot do
- **Invites a first message** — one concrete prompt beats "Ask me anything"

```text
Hi — I'm Acme's support assistant. I can help with invoices, refunds,
plan changes, and failed payments. What do you need?
```

## What a bad one does

```text
Hi! 👋 I'm so excited to help you today! How can I assist?
```

Nothing about scope, nothing about what is possible, and an emoji. The visitor now has to guess, and most will close the tab.

## Keep it short

It renders in a widget header area. Three lines is plenty. Anything longer and it pushes the input out of view on mobile, which is where most widget traffic comes from.

## Matching the prompt

If the welcome message promises something the system prompt does not deliver, you have made it worse. Write the prompt first, then describe what it actually does.

## Where it lives

Set it on the agent, not the widget — that way every channel greets people the same way, and you change it in one place.

An agent can be deployed to several channels with different looks, but the welcome message is the agent's. If you need genuinely different greetings per surface, that is a prompt-level distinction, not a widget setting.
